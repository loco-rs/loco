# Loco 1.0 — Ground-Up Documentation Overhaul (Design)

**Status:** Approved scope, pending spec review → implementation plan.
**Date:** 2026-07-03
**Owner model:** Opus governs (reviews/gates against code); implementer agents draft.
**Landing policy:** local commits only; user performs all GitHub/crates.io actions.

---

## 1. Goal

Replace Loco's documentation with a **complete, ground-up rewrite** for **v1.0.0**
(a major version jump), organized by the **Diátaxis** framework, in which **every
technical claim and code sample is verified against the actual codebase** and kept
true by CI. The rewrite targets the 1.0 API line: Sea-ORM 2.0, sqlx 0.9, edition
2024, 64-bit (`i64`) primary keys, priority queues, narrowed error enum.

Non-goals: rewriting the marketing homepage, blog, or casts; changing the Zola
theme; documenting external starter repos as if they were framework code.

## 2. Constraints (binding)

1. **Only verified docs.** No sample ships unless it is checked against the real
   API. Enforced by a compile/CI spine (§5), not by eyeballing.
2. **Diátaxis discipline.** Every page is exactly one of Tutorial / How-to /
   Reference / Explanation, authored via the `documentation-writer` skill.
3. **Local commits only.** Branch per logical unit; the user pushes/publishes.
4. **Publish still gated on Sea-ORM 2.0.0 stable** (only `-rc` exists today).

## 3. Ground truth (already produced — Phase 0 ✅)

A verified feature inventory of the entire framework, built by 8 subsystem
research passes against the code, is persisted at
`docs/superpowers/specs/2026-07-03-loco-1.0-inventory/`
(`00-MASTER-coverage-matrix.md` + `01`–`08`). It records, per feature:
public API (`file:line`), config knobs, feature flags, generator/CLI support, and
a MISSING/THIN/STALE/ACCURATE rating of current coverage. **This is the source
material for every page below** and must be re-consulted (and re-verified against
`HEAD`) at authoring time. The master matrix's Tier-1→3 ranking sets authoring order.

Headline verified 1.0 facts every page must honor (from the matrix §B):
`int` field-type → i64/BIGINT; i64 PKs + BigInteger FKs; priority queues +
`perform_later` returns job-id `String` + Redis fully supported; mailer TLS modes
(`starttls`/`implicit`/`none`, 465) override `secure`; feature is `auth_jwt`
(HS512 default, base64 secret, multi-location JWT); error enum narrowed
(`#[non_exhaustive]`, removed `EnvVar`/`Hash`/`SemVer`/`TaskJoinError`); edition
2024 (`set_var` needs `unsafe`); `embedded_assets` swaps view engine + static mw.

## 5. The verification spine (load-bearing)

The mechanism that makes "only verified docs" durable:

1. **Compiled examples app in-repo.** A `docs-site/examples/` (or reuse `examples/`)
   Cargo member that contains the real, compiling code the docs quote. Built in CI.
2. **`snipdoc` promoted to blocking.** Docs pull snippets from the examples app /
   source via `snipdoc`; the `docs.yml` workflow's `snipdoc check` flips from
   `continue-on-error: true` to blocking **once drift is cleared** (current baseline:
   5 drifted files, 13 undefined snippet ids — must be reconciled first).
3. **Doctests** for crate-level API examples where a full example app is overkill.
4. **`llms-check`** (already shipped) continues to guard the LLM files' links/versions.

Sequencing note: the spine (2) can only go blocking *after* the authoring pass
replaces stale snippets — so "flip to blocking" is the closing gate of Phase 3,
not the opener.

## 6. LLM context regeneration

`llms.txt` + `llms-full.txt` are refreshed from 0.17.x → **1.0** (version markers,
Sea-ORM 2.0, edition 2024, i64, priority queues, mailer TLS, `auth_jwt`). They stay
**curated** (the 0.18 investigation proved curated beats naive generation), but are
regenerated to match the new IA and guarded by `llms-check`. `AGENTS.md` re-verified
against the rewritten how-tos.

## 7. Phased plan

- **Phase 0 — Index & verify** ✅ done (inventories + master matrix).
- **Phase 1 — Spine & scaffolding.** Stand up the examples app + `snipdoc` wiring
  (non-blocking initially); create the Zola section skeleton for the 4 quadrants;
  reconcile the existing `snipdoc` drift baseline.
- **Phase 2 — Reference tier first.** Author the 10 Reference pages (they are the
  most mechanical and highest-value gap; nearly transcribed from inventories). Each
  via `documentation-writer`: type=Reference, outline → gate against code → write.
- **Phase 3 — How-to + Tutorials + Explanation.** Author recipes and lessons on top
  of the now-solid reference; correct all STALE facts; migrate/decompose strong
  pages. Close by flipping `snipdoc` to blocking.
- **Phase 4 — LLM context + nav + redirects.** Regenerate `llms.txt`/`llms-full.txt`
  + `AGENTS.md`; finalize Zola nav; add redirects from old URLs to new IA (the
  `llms.txt` links and any external inbound links must not 404).

## 8. Governance & workflow (per page)

Implementer agent drafts a page → invokes `documentation-writer` (decide
type/audience/goal/scope → propose outline → write) against the relevant inventory
section → Opus reviews the draft **against the cited `file:line` code**, rejects any
unverified claim → snippet extracted to the examples app / doctest → commit. Ledger:
this spec + the master matrix track page status.

## 9. Risks & open items

- **Session/usage limits** throttle parallel authoring (hit once during Phase 0).
  Mitigation: Reference tier is transcription-heavy and can proceed in smaller batches.
- **`snipdoc` drift baseline** must be cleared before the spine can go blocking.
- **URL churn** from the IA change → redirects are mandatory (Phase 4) to avoid
  breaking `llms.txt` and inbound links.
- **Starter-repo claims:** auth/user flows live in external starters, not this repo;
  document them as starter behavior, verified against the starter repo, never as
  framework API.
- **Version story:** crates move 0.17.0 → **1.0.0**; still gated on Sea-ORM 2.0.0
  stable to publish. Doc version markers target 1.0.
