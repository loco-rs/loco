# Sea-ORM 2.0 Migration — Research Notes (for Loco 0.17.0)

Date: 2026-07-01. Source of truth for the Epic A migration + the user-facing
migration guide. Sea-ORM 2.0 is currently **`2.0.0-rc.41`** (no stable release
yet; max stable is 1.1.20). Publish of loco 0.17.0 is **gated on sea-orm 2.0.0
stable** unless the user opts to ship on the rc.

## Forced environment changes (non-negotiable if we adopt sea-orm 2.0)

- **Rust edition 2024, MSRV 1.85.** Sea-ORM 2.0 requires it → Loco workspace
  must move to edition 2024 + `rust-version = "1.85"`.
- **sqlx 0.8 → 0.9.** Required for sea-orm 2.0 compatibility. Loco currently
  pins `sqlx = "0.8.2"` in both deps and dev-deps (bg_pg/bg_sqlt workers + tests).
- Migration crates must use **tokio**, not async-std (Loco already uses tokio).

## Key accelerators (adopt with credit, don't migrate blind)

- **SeaQL maintains a fork of Loco already on sea-orm 2.0**:
  https://github.com/SeaQL/loco — the official guide points users here as the
  interim. Study its diff against upstream; adopt the mechanical migration.
- **Community PR #1698** (loco-rs/loco) attempted the sea-orm 2.0 upgrade
  (marked CONFLICTING/DIRTY at M1 triage). Credit the author; reconcile.

## Breaking-change checklist (from official 2.0 migration guide)

### SeaQuery / expression layer
- `ExprTrait` now required in scope for `.eq()/.like()/.add()` etc. →
  add `use sea_orm::ExprTrait;` wherever Expr methods are used.
- Bare value literals must be wrapped: `Expr::col("type").eq(Expr::value("table"))`.
- `Alias::new("x")` → just `"x"` (string literals implement the trait).
- `ConditionExpression::Expr(..)` wrapping removed → use `.into()`.
- `Iden::unquoted` signature changed to `fn unquoted(&self) -> &str` (only
  matters if we hand-implement Iden).

### Query execution
- SeaQuery statements passed directly: `db.query_all(&query)` (no manual
  `backend.build(&query)`).
- Raw SQL methods gain `_raw` suffix: `.execute()` → `.execute_raw()`.

### Entity / ActiveModel
- `DeriveValueType` now auto-impls `NotU8`, `IntoActiveValue`, `TryFromU64` →
  delete any manual impls; custom wrapper types can now be primary keys.
- New entity format / entity-first workflow (opt-in, backward compatible).

### insert_many
- No more `.on_empty_do_nothing()`; empty insert returns
  `InsertManyResult { last_insert_id: None }`.
- `exec_with_returning_many` → `exec_with_returning` (returns `Vec<Model>`).

### Removed panics / errors
- New `DbErr` variant `BackendNotSupported` (was a panic, e.g. RETURNING
  unsupported). Any code matching on DbErr exhaustively must add the arm.

### Postgres / SQLite specifics
- Postgres `auto_increment()` now emits `GENERATED BY DEFAULT AS IDENTITY`
  instead of `serial`. Legacy behavior via feature `option-postgres-use-serial`.
  **This changes generated-migration SQL** → verify Loco's migration templates
  and snapshot tests; decide whether to opt into the legacy feature for a
  smoother user migration or embrace the new default (document it).
- SQLite: both Integer and BigInteger map to `integer` (i64). Entity generation
  flag `--big-integer-type=i32` if i32 needed.
- `sqlite-use-returning-for-3_35` on by default (needs SQLite 3.35+).

## Loco-specific surfaces to migrate (confirm via discovery)
- `src/db.rs` — ConnectOptions, DatabaseConnection, schema/transaction helpers.
- `src/model/` — ActiveModel helpers, query builders, ModelError.
- `src/testing` — MockDatabase usage.
- `loco-gen` migration + model templates (the `.t` files that emit user code).
- `loco-new/base_template` — scaffolded migrations/models + Cargo sea-orm pins.
- Snapshot tests covering generated migrations/models (insta) — will churn.
