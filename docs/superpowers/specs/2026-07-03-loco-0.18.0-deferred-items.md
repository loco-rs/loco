## Criticism log (Opus governance findings, per item)

### Item 4 — Edition 2024 (Sonnet deliverable #1, reviewed 2026-07-03)

**Governance process & honest correction.** I initially flagged the Sonnet diff
as scope creep: it collapsed ~60 nested `if let { if {` sites into let-chains
(large churn in `redis.rs`, our just-rewritten ZSET file). I reset the tree and
re-derived the migration deterministically from scratch to attribute every line.

**Finding — I was wrong; the agent did not scope-creep.** The collapses are
**gate-required**, not discretionary:
- Under edition 2024 let-chains are stable, so `clippy::collapsible_if` now fires
  on `if let X { if Y { … } }` → our `-D warnings` policy makes it a hard error.
- Exactly **32 collapses** are required workspace-wide (19 in `redis.rs`, 3 in
  `db.rs`, 2 in `etag.rs`, one each in pg/sqlt/boot/monitoring/scheduler/mirror/
  selector/logger). `cargo clippy --fix` applies precisely this set.
- The large per-file line counts (redis.rs 309, logger.rs 110) are **unavoidable
  body re-indentation** from removing a nesting level — not added logic.
- My deterministic redo (`cargo fix --edition` + `cargo clippy --fix`) reproduced
  the agent's diff **essentially file-for-file**. My "60 discretionary collapses"
  was a flawed grep double-counting multi-level nests; my `cache/mod.rs` isolation
  test misled me (that file's specific nesting wasn't collapsible).

**Credit to the agent** on two judgment calls I initially doubted:
1. `style_edition = "2021"` in `.rustfmt.toml` — correct and necessary. Without
   it, `cargo fmt` under edition 2024 reorders imports in **99 files**. Pinning
   keeps the edition-semantics bump cleanly separate from a whole-repo reformat.
2. It found the `catch_panic.rs` never-type-fallback break independently.

**Real edition-2024 semantic break fixed:** `src/controller/middleware/catch_panic.rs`
— `async { panic!() }` (type `!`) no longer coerces to `()` under 2024's
never-type fallback, so the inline closure stopped implementing `Handler`. Fixed
by extracting a named `async fn panic_handler()` with an explicit `()` signature
(the old `#[allow(dependency_on_unit_never_type_fallback)]` could silence the 2021
warning but not the 2024 hard error).

**Governance value added (not wasted):** independent deterministic reproduction of
the entire migration, full line-by-line understanding, confirmation that the
`style_edition` pin is load-bearing, and confirmation that the *only* test failure
is the pre-existing upstream-gated `test_migrations_flow` (not caused by this work).

**Deliberate deferral (my call):** generated apps (`loco-new/base_template/*.t`)
stay **edition 2021**. Editions are per-crate; the framework going 2024 does not
require it, and the generated-app path is upstream-gated (Sea-ORM 2.0.0 stable) so
a 2024 generated app cannot be verified now. Flipping the most user-facing surface
unverified is the wrong risk. → tied to the existing sea-orm-stable verification
window; flag for user override.

**Final diff:** 36 files, 471/397 (edition strings ×3 + `cargo fix --edition`
idioms + 32 `collapsible_if` collapses + catch_panic never-type fix + 13 FIXME→
SAFETY rewrites + 2 `.rustfmt.toml` pins). **Green gate — verified:** fmt ✅✅,
clippy `-D warnings` ✅ (root 0, loco-new 0), `cargo hack --each-feature` 18/18 ✅,
`test --all-features` **597 passed / 0 failed** ✅ (bgworker priority tests confirm
the redis.rs collapses are safe), loco-gen 17 lib ✅. Only failures are the two
pre-existing upstream-gated sets (test_migrations_flow; loco-new wizard matrix =
`loco-rs 0.17` unpublished) — unchanged, unrelated to edition. Committed 5a4ed712.

### Item 2 — Inflection consolidation (Opus, 2026-07-03) — PREMISE REJECTED

**Governance finding: the deferred item's premise is empirically false.** The 0.17
spec assumed the inflection crates were "redundant" and one could be dropped. They
are not: **`heck` does case conversion, `cruet` does pluralization**, and cruet's
casing is NOT a drop-in for heck's. Empirical probe (heck 0.5 vs cruet 1.0 on 23
realistic inputs → **16 differences**), the damaging ones being digit/acronym
handling: `i32`→`i_32`, `f64`→`f_64`, `v2`→`v_2`, `HTTPServer`→`Httpserver`,
`APIKey`→`Apikey`. loco-gen casings **type names and identifiers**, so routing
casing through cruet would corrupt generated code (e.g. `Vec<i32>` field types,
versioned names). And `infer.rs` snake-cases user-typed *migration names*, so a
library swap would change table inference for digit/acronym names while the
existing (simple-name) tests still pass — a silent regression.

**Conclusion:** every call site's crate choice is load-bearing; there is **no
output-neutral consolidation**. Forcing one would be actively harmful. Delivered
instead: keep both crates, and **codify the convention** (cruet = pluralization
only; heck = all casing, with the evidence) as a doc comment on the inflection hub
(`loco-gen/src/infer.rs`) so the split is intentional, not accidental drift.
Comment-only, zero behavior change. Committed 4a7856c0. **Flagged for user** — if
they want a forced library reduction anyway, I advise against it (I'd have to
change generated output).

### Item 5 — llms.txt pipeline (Sonnet #6 + Opus, 2026-07-03) — reframed + partially deferred

**Governance reframe.** The item asked to *generate* `llms-full.txt` from a snipdoc
spine. Investigation showed the naive version is a net negative: the current
`llms-full.txt` is a hand-curated, high-signal 15-section reference; concatenating
docs would bloat/degrade it, and the snipdoc "spine" (`snipdoc.yml`, ~29 small
command snippets) is nowhere near a source you could regenerate the reference
from. The 0.17 spec already flagged this pipeline as "gated on the spine work" —
confirmed.

**Delivered (safe, valuable): a *verification* pipeline** — `cargo xtask
llms-check` (Sonnet-built, Opus-reviewed). Resolves every `loco.rs/...` link in
llms.txt to a real docs page (ERROR on broken; I added fragment-awareness so
`#anchor` links validate the page), flags orphan pages (WARNING), checks the two
version markers agree. Wired as a **blocking** CI step in docs.yml. It immediately
caught **real shipped drift**: llms.txt linked to `docs/the-app/{configuration,
testing}/` — pages that never existed (the deferred IA pages). Repointed to real
sections (`your-project/#your-app-configuration`, `models/#testing`). Passes:
18 links, 0 broken. Committed 70918bd8.

**Evidence-deferred (NOT hand-waved — I ran `snipdoc check`):**
- **snipdoc-blocking flip** — docs.yml runs `snipdoc check` with
  `continue-on-error: true`. I installed snipdoc and ran it: **substantial drift** —
  5 files with stale snippets (workers.md, task.md, models.md, your-project.md,
  README.es.md), **13 snippet IDs referenced in docs but undefined in snipdoc.yml**
  (configuration-{auth,database,logger,mailer,queue,server,scheduler,settings},
  app-initializers, model-validation, task-code-example), and broken exec-command
  paths (`./examples/demo` absent). Flipping to blocking now would break the user's
  CI. Reconciling this (defining 13 snippets correctly, updating 5 files) is the
  "spine work" — a careful content task that risks injecting wrong content; left as
  a documented follow-up.
- **Full `llms-full.txt` auto-generation** — gated on that same comprehensive-spine
  work; the curated file currently exceeds what generation would produce.
