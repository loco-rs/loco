# Loco 0.17.0 — Big Breaking Release: Program Design

Date: 2026-07-01
Owner: Dotan J. Nahum (with Claude / Opus 4.8)
Status: Approved direction (version + scope + mandate settled); executing.

> **Supersedes** the "modernize in place, no breaks" framing in
> `2026-06-28-loco-maintenance-modernization-design.md`. That doc's M1 is done
> and its M3/M4 intents carry forward here as Epics C and D. Sea-ORM 2.0, edition
> 2024, and public-API breaks — previously deferred — are now **in scope**.

## Decisions (settled with user, 2026-07-01)

1. **Version:** `0.17.0` (honest 0.x breaking bump; not committing to 1.0 yet).
2. **Scope:** one **mega-release** — breaking code + Sea-ORM 2.0 + first-class
   LLM support + full docs restructure/rewrite, shipped together.
3. **Publish mandate:** **prep-only.** I take everything to release-ready on
   local branches (green build/clippy/tests, version bumps, CHANGELOG, migration
   guide, hand-off list). The user pushes, tags, and `cargo publish`.
4. **Contributors:** adopt community PRs with credit (`Co-authored-by`).

## Hard external constraints

- **Sea-ORM 2.0 is not yet stable** — latest is `2.0.0-rc.41` (max stable
  1.1.20). **The crates.io publish of 0.17.0 is GATED on sea-orm 2.0.0 final.**
  All prep proceeds against the rc so we are day-one ready; the user may choose
  to ship on the rc.
- Adopting Sea-ORM 2.0 **forces**, non-negotiably:
  - **MSRV 1.85** (toolchain floor). Edition is per-crate, so Loco can consume
    edition-2024 sea-orm while staying edition 2021 — confirmed by the SeaQL
    fork, which bumped sea-orm **without** an edition change. Moving Loco itself
    to **edition 2024** is therefore optional modernization → **Epic B**, not a
    hard prerequisite here.
  - **sqlx 0.8 → 0.9** (Loco uses sqlx directly for bg_pg/bg_sqlt + tests).
- **Accelerators (adopt with credit):**
  - **SeaQL's fork** https://github.com/SeaQL/loco already migrated Loco to
    sea-orm 2.0 in **3 commits / 10 files / +157-123** on top of our current
    master (`e9598a68`): `Cargo.toml`, `loco-new/base_template/Cargo.toml.t`,
    `.../migration/Cargo.toml.t`, `src/bgworker/pg.rs`, `src/bgworker/sqlt.rs`,
    `src/db.rs` (+99-74), `src/model/query/dsl/mod.rs`, `src/schema.rs` (+30-3),
    `src/testing/db.rs`, `src/tests_cfg/db.rs`.
  - Community PR **#1698** (elcoosp, "Sea ORM 2.0", CONFLICTING) — credit/reconcile.

Detailed breaking-change checklist: `2026-07-01-seaorm-2.0-migration-notes.md`.

## Guiding principles

- Green after every slice. Each slice is its own branch/commit, verified
  (build + clippy pedantic/nursery + `cargo hack check --each-feature` + tests
  with testcontainers + sanity scaffold/boot) before the next.
- Breaking changes are allowed **and must be documented** — every break lands a
  CHANGELOG entry and a migration-guide stanza the same commit it's introduced.
- One verified source of truth feeds human docs **and** LLM artifacts.
- Adopt upstream/community work with credit; don't re-derive what SeaQL already
  proved out.

## Epics

Tracked as tasks #7–#11. Ordering reflects dependencies: A is foundational
(nothing else compiles on the new toolchain until it lands); B rides on A; C and
D consume the stabilized surface; E gates the release.

### Epic A — Sea-ORM 2.0 + toolchain foundation  *(task #7)*

Foundational and highest-risk. Slices:

- **A0 — MSRV floor.** Workspace + all template `Cargo.toml(.t)` `rust-version =
  "1.85"`; add/adjust `rust-toolchain`; bump `doctor.rs` min Rust. No edition
  change (that's Epic B). Verify still green on sea-orm 1.1.
- **A1 — Adopt SeaQL sea-orm 2.0 diff.** Apply the 10-file migration (credit
  SeaQL) against current master; bump sea-orm/sea-orm-migration to `2.0.0-rc.41`,
  sqlx to `0.9`, sea-orm-cli min ver in `doctor.rs`. Reconcile with our HEAD.
- **A2 — Migration DSL (`src/schema.rs`).** The ~100-arm `ColType::to_def`,
  `SchemaManager` wrappers, `sea_query` helper renames, ExprTrait imports,
  `Alias::new` → string, postgres `Type::create`. Highest per-line risk.
- **A3 — Generator + template output.** `loco-gen` migration/model templates
  and `loco-new/base_template` entities/migrations/models emit sea-orm 2.0 code;
  regenerate all insta snapshots; entity header `sea-orm-codegen 2.0`.
- **A4 — Verify end-to-end.** DB tests (pg+sqlite via testcontainers), generated
  app boots + migrates + seeds; decide Postgres `serial` vs
  `GENERATED … IDENTITY` (feature `option-postgres-use-serial` for smoother user
  migration, or embrace new default + document).
- **A5 — Migration-guide stanza** for Sea-ORM (users' `m_*.rs`, models, Cargo).

**Exit:** all features build on sea-orm 2.0 rc, full suite green, generated app
boots; Sea-ORM migration-guide section written.

### Epic B — Breaking modernization & dependency upgrades  *(task #8, absorbs #4)*

Behind the green suite, each its own slice + CHANGELOG/migration note:

- **Dep majors:** `thiserror 1→2`, `tower 0.4→0.5`, `heck 0.4→0.5` (unify; two
  in-tree), `serde_yaml` (archived) → maintained fork, `byte-unit 4→5` or drop,
  `testcontainers 0.23→latest`, `opendal 0.54→latest`, `redis`+`bb8-redis`,
  `validator 0.20→latest`, `tokio-cron-scheduler`, `ipnetwork`, `strum 0.26→0.27`,
  `tabled`/`cargo_metadata` (xtask), `rstest` unify (3 versions in-tree),
  `cruet`/`colored`/`rand`/`duct` version skew across crates. Fold M1 dependabot
  (#1772/#1760/#1754) here.
- **Replace hand-rolled with crates / cut LOC:**
  - `depcheck.rs` Cargo.lock parsing → `cargo-lock` crate (done); `cargo_config`
    trimmed to its Cargo.toml metadata reader.
  - Consolidate `cruet` + `heck` to one inflection crate. **Decision 2026-07-02:
    retain both.** cruet (pluralize) is a superset of heck (case), but swapping
    heck→cruet for case conversion under a snapshot-tested *code generator* risks
    subtle identifier changes in user-generated code (acronyms/number edge cases)
    — not worth a one-dependency saving. Both are small, maintained crates.
  - De-duplicate the three bgworker backends (pg/sqlt/redis ≈ 4400 lines, largely
    parallel) behind a shared trait/driver. **Decision 2026-07-02: DEFER to a
    focused follow-up.** Highest-risk refactor in the epic; all three backends
    are container-integration-tested and orthogonal to the release's core goals
    (breaking + Sea-ORM 2.0 + LLM + docs). Better done in isolation than folded
    into the mega-release. Tracked as a post-0.17 item.
  - Retire single-use crates: `duct_sh` (done — replaced by `duct` shell cmd).
    **Decision 2026-07-02: retain `english-to-cron` and `backtrace_printer`** —
    both are loco-owned single-purpose crates providing real functionality
    (english→cron phrase parsing; backtrace frame filtering). Churning them to
    save a dependency line adds reimplementation risk on user-facing/cosmetic
    behavior for no meaningful gain.
  - Drop dead `loco-cli` crate (15-line stub, superseded by `loco-new`) — done.
  - Split `src/db.rs` (1829) / `config.rs` by concern. **Decision 2026-07-02:
    DEFER.** Purely-internal reorganization with real churn risk (git blame,
    import paths) and no user-facing value; not worth folding into a release
    already carrying Sea-ORM 2.0 + breaking API + LLM + docs. Post-0.17 item.

  **B-struct net:** the high-value structural wins landed (dead-crate removal,
  `duct_sh` retired, hand-rolled Cargo.lock parsing → `cargo-lock`). The risky
  (bgworker dedup, inflection consolidation) and cosmetic (file splits) items are
  deliberately deferred to focused follow-ups so the mega-release stays on its
  core goals.
  - Split `src/db.rs` (1829) by concern; split `config.rs` types vs loader.
- **API cleanup (breaking).** Re-scoped 2026-07-02 after inspection:
  - `#[non_exhaustive]` on the public `Error` enum — **done** (future-proofs the
    API; migration note + CHANGELOG landed). The highest-value, correct item.
  - **Retain** the `prelude` sea-orm/axum re-exports: they are *named* (not glob)
    and are required by generated models/controllers — stripping them breaks
    generated code and the framework's ergonomics.
  - **Retain** `prelude::Validate` (used by generated `users.rs`) and the
    `axum_test::TestServer` re-export (real testing ergonomics; generated tests
    lean on it). Leaking a major version is the accepted tradeoff for a
    batteries-included framework.
  - **Retain** `env_vars::get_or_default` — **not dead** (live at `db.rs:760`);
    the original bullet was wrong.
  - Narrowing the 39-variant `Error` / removing `Error::Any`: deferred; churny
    and low-value versus the `#[non_exhaustive]` hardening already shipped.
- **Idioms:** `impl AsyncFn` (#1657); `cargo fix`/clippy pedantic sweep on 2024.
- **Roadmap feature PRs that fit a breaking release** (evaluate, adopt with
  credit): mailer implicit TLS #1774, scheduler-without-worker #1742, job IDs
  #1624, priority queue #1693, PagerMeta #1685.

**Exit:** current deps, measurable LOC reduction, cleaner public API, all green.

### Epic C — First-class LLM support  *(task #9)*

Greenfield (no AGENTS.md/llms.txt/skill exists today).

- One verified source (snipdoc spine + `src/prelude.rs` API index + real
  `--help` capture) → generated `llms.txt` (index) + `llms-full.txt` (full).
- A Loco **skill / AGENTS.md** teaching the all-in-one model: routing, models &
  migrations, controllers, workers, scheduler, mailers, tasks, config, testing —
  the areas LLMs get wrong precisely because Loco is batteries-included.
- **Scaffold agent context into every `loco new` app** (AGENTS.md + skill/cursor
  rules) via `loco-new/base_template` + `loco-gen`.

**Exit:** a 1M-context model armed with the artifact builds a correct 0.17 Loco
app; new projects ship agent context.

### Epic D — Docs restructure & rewrite  *(task #10)*

- Fix + enforce the source-of-truth spine: restore the ~7 orphaned
  `inject_from="code"` snip tags (only `initializers-trait` exists today),
  fix/replace the missing `examples/demo` exec working-dir, then flip
  `snipdoc check` to **blocking** in `.github/workflows/docs.yml` (drop
  `continue-on-error` + `SNIPDOC_SKIP_EXEC_COMMANDS`).
- Restructure IA: add dedicated **config** and **testing** pages; move auth into
  getting-started; fill the websocket stub; de-concentrate controller.md (1418)
  and pluggability.md (928). Move hand-maintained homepage examples in
  `config.toml` under snipdoc.
- Rewrite for accuracy against 0.17 code (esp. models.md migration/entity
  examples → sea-orm 2.0).
- **Migration guide 0.16 → 0.17** — the headline user-facing deliverable — lands
  in `extras/upgrades.md`, assembled from each epic's per-slice stanzas.
- README consolidation (PR #1762): single templated source → root + 7
  translations; base_template README links rather than restates.

**Exit:** `snipdoc check` blocking and green; coherent IA; docs provably match
0.17 code; complete migration guide.

### Epic E — Release engineering for 0.17.0  *(task #11)*

- **CHANGELOG.md** in Keep-a-Changelog form, assembled continuously from slice
  entries (Added / Changed / **Breaking** / Fixed / Removed).
- **Version bumps** across the workspace: `loco-rs`, `loco-gen`, `loco-new`,
  starters, and every template pin; reconcile the sea-orm-migration 1.0.0 vs
  1.1.0 skew as part of the 2.0 bump.
- **Green gate** (the release checklist): fmt, clippy pedantic/nursery, `cargo
  hack check --each-feature`, `test --all-features` (testcontainers pg+redis),
  loco-gen + loco-new matrices (`LOCO_DEV_MODE_PATH`), sanity scaffold+build+boot.
- **Hand-off action list** for the user: branches to push, PRs to open, community
  PRs to merge/close/credit, and the **publish sequence gated on sea-orm 2.0.0
  stable** (bump rc→final, re-verify, tag, `cargo publish` in dependency order:
  loco-gen → loco-rs → loco-new).

**Exit:** a single reviewed, green, release-ready state + an explicit,
ordered hand-off the user can execute.

## Risk register

| Risk | Mitigation |
|---|---|
| sea-orm 2.0 rc shifts before stable (rework) | rc.41 is very late; adopt SeaQL's proven diff; re-verify at 2.0.0 final (a gated step). |
| Edition 2024 migration breaks many crates at once | Do A0 as its own slice, `cargo fix --edition` per crate, green before touching sea-orm. |
| `verify_access` matches sea-orm internal enum variants | SeaQL diff already handles `db.rs`; adopt theirs. |
| Postgres `serial`→`IDENTITY` changes users' migration SQL | Decide + document explicitly (A4); likely opt into `option-postgres-use-serial` for a gentler user migration. |
| Snapshot churn hides real regressions | Review every regenerated `.snap` diff by hand, not blind `INSTA_UPDATE=always`. |
| Scope creep across 4 epics stalls the release | Each slice independently green + committed; E assembles continuously; publish gated but everything else lands incrementally on branches. |
| Prep-only: I must not push/publish | Enforced; E produces the hand-off, user executes GitHub/crates.io. |

## Out of scope

- 1.0 stability commitment; from-scratch rewrite; MCP server.
- Publishing to crates.io / pushing to GitHub (user's action).
