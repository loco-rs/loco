## Evidence log (numbered findings)

1. **FACT**: `dump_tables`'s per-cell type-probing chain (`db/schema.rs:196-238`) tries, in order: `serde_json::Value`, `String`, `i8`, `i16`, `i32`, `i64`, `f32`, `f64`, `uuid::Uuid`, `DateTime<Utc>` — there is no `bool` arm anywhere in the chain. For a genuine Postgres `BOOLEAN` column (a real SQL type, distinct from integer at the wire/type-check level), every one of those `try_get::<T>` calls will fail a type check, `value_result` becomes `None` (`.ok()` at `db/schema.rs:238`), and the column is silently omitted from the row (`if let Some(mut value) = value_result` at `db/schema.rs:240` — no `else`/warning branch). The only reason the shipped test (`db/schema.rs:394-508`, `sqlite_dump_tables_roundtrip`) doesn't catch this is that it runs against **SQLite only**, where booleans are physically stored as `INTEGER` and so are captured by the `i8` arm. → **JUDGMENT**: this is a silent-wrong bug on the Postgres path that the one existing test cannot detect because it never runs on Postgres. → KPI4, KPI6. **Severity: HIGH.**

2. **FACT**: `connect::create` builds the "connect to admin db" URL via `db_uri.replace(db_name, "/postgres")` (`connect.rs:173`), and `str::replace` rewrites **every** occurrence of the substring, not just the path segment. A URI like `postgres://myapp:myapppass@localhost/myapp` (username/password happen to contain the db name as substring) will have all three occurrences replaced, corrupting the credentials. The shipped test `test_postgres_create_database` (`connect.rs:416-451`) uses a URL without matching credentials, so it does not exercise this path. → **JUDGMENT**: fragile string-typed manipulation of a structured value (a URL) rather than using a URL parser to swap only the path component. → KPI4, KPI6. **Severity: HIGH.**

3. **FACT**: `verify_access` (`connect.rs:60-81`) only implements a real check for `DatabaseBackend::Postgres` (line 62) and `Disconnected` (line 75); every other backend, including MySQL and SQLite, falls into the wildcard `_ => {}` (line 78) and returns `Ok(())` unconditionally. → **JUDGMENT**: the function's name and doc-comment ("Verifies a user has access...") promise a guarantee it does not deliver for two of the three supported backends — silent false-positive success. → KPI4, KPI6. **Severity: MEDIUM-HIGH.**

4. **FACT**: `src/schema.rs` is 991 lines (verified via `wc -l`) and contains no `#[cfg(test)] mod tests` block anywhere in the file (verified via grep for `#[cfg(test)]`/`#[test]` — zero matches), despite implementing non-trivial logic: FK constraint naming (`schema.rs:690-701,787-798,873-880`), table/column-name pluralization+singularization via `cruet` (`schema.rs:708-715`), nullable-reference suffix parsing (`schema.rs:666-669`), and enum-type lifecycle management (`schema.rs:123-159,920-991`). → **JUDGMENT**: this is the single most safety-critical file in the area (bad FK naming/normalization silently produces broken migrations users only discover at `loco db migrate` time) and it is completely unverified by unit tests. → KPI6. **Severity: HIGH.**

5. **FACT**: `reference_id()` is called with a **normalized** table name in `create_table_impl` (`schema.rs:648`, `reference_id(&nz_from_table)`) but with the **raw, un-normalized** parameter in both `add_reference` (`schema.rs:780`, `reference_id(totbl)`) and `remove_reference` (`schema.rs:864`, `reference_id(totbl)`). → **JUDGMENT**: three call sites computing "what should the FK column be called" from the same conceptual input use two different normalization strategies; while `cruet::to_singular` may coincidentally converge on most already-conventional (snake_case, already-plural) inputs, this is an inconsistent-handling-of-the-same-concept smell that risks drift for less-conventional table names (mixed case, already-singular, etc.), producing a column name in `create_table`/`create_join_table` that `add_reference`/`remove_reference` wouldn't independently reconstruct. → KPI1, KPI4. **Severity: MEDIUM.**

6. **FACT**: `schema.rs:352-354`, `:358-360`, `:387-389` contain commented-out `ColType` match arms (`// Self::TinyInteger => tiny_integer(name),` etc., `// Self::Timestamp => timestamp(name),`) left inside the live `to_def` match statement. → **JUDGMENT**: literal dead/commented-out code in the live tree — an explicit patch-on-patch smell called out by the rubric. → KPI1. **Severity: LOW-MEDIUM.**

## Patch-on-patch smells (specific, cited)

- Commented-out dead `ColType` match arms left in-line: `schema.rs:352-354,358-360,387-389`.
- `schema.rs` has 41 historical commits touching it (via `git log --oneline -- src/schema.rs`), consistent with organically-added variants (e.g. the Sea-ORM-2.0 64-bit-PK comment at `schema.rs:330-332`, the Array/Enum groups added later at `schema.rs:276-284`) versus `db/schema.rs` which has exactly 1 commit in its history — the two "schema" files are not just conceptually unrelated but were built on completely different timelines, reinforcing that the shared name is coincidental, not a designed pairing.
- `db/entities.rs:132-134` — explicit version-drift shim: `fix_entities()` string-matches and deletes a specific literal (`"impl ActiveModelBehavior for ActiveModel {}"`, `entities.rs:151,155-159`) from sea-orm-cli-generated files, with a comment linking to an upstream sea-orm PR (`entities.rs:132`) — a workaround for another crate's behavior baked into the live tree with no version gate (it will silently keep doing this even after the upstream issue is fixed and would need to be discovered/removed manually).
- Inconsistent raw-SQL identifier quoting: `db/schema.rs:174` quotes the table identifier (`format!(r#"SELECT * FROM "{table}""#)`), while `db/seed.rs:85-87,96-98,130-131,139-140,181-183,193-195` interpolate `table_name` unquoted into SQL strings — same "build SQL with a table name" concern handled two different ways in the same area.
- `#[allow(clippy::cognitive_complexity)]` at `db/schema.rs:146` and `#[allow(clippy::too_many_lines)]` at `schema.rs:327` — both clippy suppressions on the exact functions this audit flags as needing decomposition (dump_tables' type-probing chain, and `ColType::to_def`'s mega-match).

## Library hypotheses

- **HYPOTHESIS**: `ColType` (`schema.rs:162-470`, ~300 LOC of enum + match) could shrink materially by dropping the enum entirely and exposing the already-imported `sea_orm_migration::schema::*` builder functions directly plus a couple of small combinator helpers (nullable/unique/default as builder methods on `ColumnDef`, which sea-orm already supports). No new crate needed — this is "stop wrapping, delegate directly" rather than "add a dependency." Risk: this is loco's public migration-authoring surface (used by `loco generate migration field:type` codegen in `loco-gen`), so it's an actual breaking-API change, not a drop-in — **NEEDS SPIKE** to check how tightly `loco-gen`'s field-type parser is coupled to `ColType`'s variant names.
- **HYPOTHESIS**: `db/schema.rs`'s hand-rolled per-cell type-probing chain (`db/schema.rs:196-238`) is working around the lack of a generic "decode any SQL value to `serde_json::Value`" API in `sea_orm`/`sqlx`. `sqlx`'s own `Any` driver or `serde_json` support in the underlying Postgres driver may already offer a single dynamic decode path keyed off the column's reported type (`sqlx::Column::type_info()`), which would remove the ordered-guessing and directly fix the boolean bug (finding 1) instead of extending the OR-chain further. Risk: `sea_orm`'s `QueryResult` wraps the driver row and may not expose enough type metadata to make this simpler than just adding the missing `bool` arm — **NEEDS SPIKE**.
- **HYPOTHESIS**: `connect::create`'s manual database-name/path substring replacement (`connect.rs:161-177`) could use the `url` crate (already a common transitive dependency in the Rust web/DB ecosystem) to parse the URI and replace only the path segment, eliminating the whole-string `.replace()` bug (finding 2). Risk: connection URIs here aren't always strictly RFC 3986 URLs (e.g. `sqlite://./relative/path.sqlite`, tested at `connect.rs:366-367`), so `url::Url::parse` may reject inputs the current regex-based `extract_db_name` (`connect.rs:13-17`) happily accepts — **NEEDS SPIKE**, and would likely apply only to the Postgres-only `create()` path, not `extract_db_name` generally.

## What is genuinely excellent (cited — be specific)

- `src/db/migrate.rs` (78 lines total) is a model "thin layer over sea-orm": `converge` (17-37) cleanly sequences reset/migrate/truncate by config flag, and `migrate`/`down`/`status`/`reset` (44-78) are each 1-3 line delegations straight to `MigratorTrait`. Zero reinvention, fully readable in one sitting.
- `src/db/mod.rs` (23 lines) is an exemplary minimal facade — five private submodules, one glob re-export each, one shared `IGNORED_TABLES` constant. No ceremony.
- `src/model/query/paginate/mod.rs`'s doc-comments (`paginate/mod.rs:87-145,180-203`) are runnable doctests showing three real usage variants (no condition / with condition / with order-by) rather than prose — genuinely useful, verifiable documentation.
- The FK-nullability handling in `create_table_impl` (`schema.rs:665-701`) correctly derives `ON DELETE SET NULL`/`NO ACTION` vs `CASCADE`/`CASCADE` from a `?`-suffix convention (`schema.rs:666-669`) and documents *why* (Rails-derived convention), and the SQLite FK-on-alter limitation is explicitly explained with an upstream-blog citation rather than silently doing the wrong thing (`schema.rs:812-833`).

## Top 3 things that would most raise the area's quality

1. Fix the `dump_tables` boolean-column silent-drop bug (`db/schema.rs:196-238`) and add a Postgres-backed test (the existing test at `db/schema.rs:394-508` is SQLite-only) — this is the one confirmed silent-correctness bug in the area.
2. Add a unit test module to `src/schema.rs` covering `normalize_table`/`reference_id` pluralization edge cases and FK-name generation across `create_table_impl`/`add_reference`/`remove_reference`, and resolve the normalized-vs-raw `reference_id()` input inconsistency found at `schema.rs:648` vs `schema.rs:780,864`.
3. Replace `ColType`'s ~120 hand-enumerated variants (`schema.rs:162-284`) with a smaller composable representation (base type + null/unique/default flags) sitting directly on top of `sea_orm_migration::schema`'s existing builder functions, cutting the mega-match (`schema.rs:328-470`) and removing the commented-out dead variants along the way.
