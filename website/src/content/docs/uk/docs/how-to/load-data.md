Мета: дати вашому застосунку доступ до даних лише для читання, що зберігаються у JSON-файлі — завантажених один раз і утримуваних у пам'яті — без розгортання таблиці в базі даних чи ручного файлового вводу-виводу.

Це гарний вибір для даних, які читають набагато частіше, ніж змінюють: гіперпараметри машинного навчання, IP-бан-лист, події календаря, біржові дані, політики безпеки, конфігурація на рівні контейнера. Якщо дані змінюються з кожним запитом, скористайтеся натомість [кешем](/uk/docs/how-to/use-cache/) або базою даних.

## 1. Згенеруйте завантажувач даних

```
$ cargo loco g data stocks
added: "data/stocks/data.json"
added: "src/data/stocks.rs"
injected: "src/data/mod.rs"
* Data loader `Stocks` was added successfully.
```

Це створює файл `data/stocks/data.json` (поруч із `src/`, так само, як `config/` лежить поруч із `src/`) та модуль `src/data/stocks.rs` у просторі імен `crate::data::stocks`.

## 2. Сформуйте структуру даних

`src/data/stocks.rs` спочатку містить структуру-заглушку:

```rust
#[derive(Debug, Clone, Serialize, Deserialize, Default)]
pub struct Stocks {
    pub is_loaded: bool,
}
```

Замініть її структурою, що відповідає справжній формі `data/stocks/data.json` (інструменти на кшталт [quicktype](https://quicktype.io/) можуть згенерувати її з прикладу файлу). Підходить будь-який тип, сумісний із `serde`.

## 3. Завантажте дані

Під капотом згенерований модуль викликає `loco_rs::data`, який надає дві функції завантаження:

```rust
// асинхронна — використовуйте з контролерів, воркерів, задач
pub async fn load_json_file<T: DeserializeOwned>(path: &str) -> Result<T>;

// синхронна — використовуйте під час завантаження застосунку або поза асинхронним контекстом
pub fn load_json_file_sync<T: DeserializeOwned>(path: &str) -> Result<T>;
```

Обидві розв'язують `path` відносно теки даних — типово `data/`. Викликайте `data::stocks::get()` звідусіль, щоб читати копію в пам'яті, завантажену один раз на час життя процесу; викликати її стільки разів, скільки завгодно, дешево. Викликайте `data::stocks::read()`, якщо натомість хочете щоразу перечитувати дані прямо з диска (це коштує операцію введення-виведення при кожному виклику).

## 4. Вкажіть іншу теку даних (опційно)

Тека даних типово дорівнює `data/`, розв'язаній відносно того, де запускається бінарник застосунку. Встановіть змінну середовища `LOCO_DATA`, щоб перевизначити її:

```
LOCO_DATA=/etc/myapp/data cargo loco start
```

На кожній машині, де запускається бінарник, поруч із ним має бути тека `data/` (або шлях із `LOCO_DATA`) — так само, як потрібен `config/`.

## Оновлення даних

Оскільки копія в пам'яті завантажується один раз на процес, підхоплення нових даних означає перезапуск процесу — концептуально схоже на деплой, але без перекомпіляції чи постачання нового коду, тож це швидко. Якщо потрібно оновити дані без перезапуску, викликайте функцію `read()` безпосередньо та кешуйте результат самостійно за допомогою системи [кешу](/uk/docs/how-to/use-cache/).
