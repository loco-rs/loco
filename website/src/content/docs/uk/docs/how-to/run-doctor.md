Мета: швидко перевірити, чи правильно налаштоване середовище вашого застосунку (база даних, черга, інструменти, версії залежностей) — як локально, так і в CI.

## 1. Запустіть його

```sh
cargo loco doctor
```

Кожна перевірка виводить один рядок зі значком статусу, а коли є щось, що варто виправити, — опис на наступних рядках:

```
✅ DB connection: success
✅ queue connection: success
❌ SeaORM CLI was not found
   To fix, run:
      $ cargo install sea-orm-cli
```

- ✅ = `Ok`
- ❌ = `NotOk`
- ⚠️ = `NotConfigure` (ресурс не налаштований — це не обов'язково помилка)

Якщо **будь-яка** перевірка поверне `NotOk`, процес завершиться з ненульовим кодом — додайте `cargo loco doctor` у CI, щоб збірка падала при розірваному з'єднанні з БД/чергою або застарілій залежності.

## 2. Що перевіряється

`doctor` завжди запускає:

| Перевірка | Умова | Що робить |
|---|---|---|
| База даних | `with-db` увімкнена | З'єднується, пінгує та перевіряє доступ за допомогою `config.database`. |
| Черга | `workers.mode` — `BackgroundQueue` | Створює провайдера черги та пінгує його; повідомляє `NotConfigure`, якщо чергу не налаштовано. |
| Перевірки ініціалізаторів | будь-який зареєстрований `Initializer` реалізує `check()` | Запускає кожен із них, додаючи до повідомлення префікс `Initializer {name}: `. |

...і, **лише коли визначене середовище не є `production`**, ще три:

| Перевірка | Що робить |
|---|---|
| Deps | Читає `Cargo.lock` і позначає будь-яку «благословенну» залежність нижче мінімальної версії. |
| SeaOrmCLI | Запускає `sea-orm-cli --version` і звіряє її з мінімальною. |
| PublishedLocoVersion | Порівнює вашу версію `loco-rs` з опублікованою на crates.io. |

Благословенні мінімальні версії: `tokio 1.33.0`, `sea-orm 2.0.0-rc`, `validator 0.20.0`, `axum 0.8.1` (мінімум `sea-orm` вказує на лінійку `2.0.0-rc`, щоб пройшли і pre-release, і стабільна `2.0`).

У `production` ці три замінюються однією перевіркою ProductionSafety, яка позначає конфігурацію, допустиму на ноутбуці, але шкідливу на сервері (loopback-`server.binding`, `logger.pretty_backtrace` та подібне).

## 3. Перевірте production-середовище

На розгорнутих середовищах зазвичай не встановлено `sea-orm-cli`, може не бути доступу до crates.io, і не потрібне нагадування «ви відстаєте по X» під час кожного запуску. Який набір перевірок запускати, визначається середовищем, яке розпізнав `doctor` — окремого фільтра немає:

```sh
cargo loco doctor --environment production
```

`--production` (коротко `-p`) — це застарілий аліас саме цієї команди. Він виводить попередження про застарілість, а потім **перемикає середовище на production**, тож він також змінює, який конфігураційний файл завантажується і яка база даних відкривається — це не спосіб запустити перевірки dev-середовища з production-фільтрацією, і ніколи не було безпечно читати його так.

## 4. Перегляньте розпізнану конфігурацію за допомогою `--config`

`--config` (коротко `-c`) повністю пропускає перевірки і натомість виводить повністю розпізнаний `Config` (у вигляді YAML) плюс назву активного середовища — корисно, коли ви не впевнені, який конфігураційний файл/середовище фактично завантажилося:

```sh
cargo loco doctor --config
```

```
# ...ваша повна розпізнана конфігурація, виведена як YAML...
Environment: development
```

Це доповнює [довідник із конфігурації](/uk/docs/reference/configuration/#завантаження-та-пріоритет) — якщо параметр виглядає не так, як ви очікуєте, `doctor --config` показує конфігурацію *після* застосування пріоритету файлів, розпізнавання середовища та Tera-шаблонізації, а не лише те, що лежить на диску.

## 5. Додайте власні перевірки

Якщо ви постачаєте власний [`Initializer`](/uk/docs/how-to/add-middleware/), реалізуйте його метод `check`, і `doctor` підхопить його автоматично — додаткового підключення не потрібно:

```rust
use loco_rs::doctor::{Check, CheckStatus};

async fn check(&self, app_context: &AppContext) -> loco_rs::Result<Option<Check>> {
    // поверніть None, щоб відмовитися від перевірки, або Some(Check { .. }), щоб повідомити результат
    Ok(Some(Check {
        status: CheckStatus::Ok,
        message: "connected".to_string(),
        description: None,
    }))
}
```

## Перевірте це

```sh
cargo loco doctor
echo $?           # 0, якщо всі перевірки пройшли, ненульове значення, якщо будь-яка перевірка NotOk
cargo loco doctor --environment production
cargo loco doctor --config
```

Дивіться [довідник CLI](/uk/docs/reference/cli/#21-підкоманди-верхнього-рівня) для точного списку прапорців разом з усіми іншими підкомандами `cargo loco`.
