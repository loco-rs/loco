Мета: змінити те, що створює `cargo loco generate <kind>` — наприклад, додати заголовок до кожного згенерованого контролера або підправити React-сторінки, які створює скафолд, — без форку Loco.

Кожен вид генератора, розглянутий у [Використанні генераторів](/uk/docs/how-to/use-generators/), керується файлами шаблонів `.t`, вбудованими в крейт `loco-gen`. `cargo loco generate override` копіює один із цих шаблонів (або цілу папку) у власну директорію `.loco-templates/` вашого застосунку; відтоді генерація використовуватиме вашу копію замість вбудованого шаблону.

## 1. Подивіться, що можна перевизначити

Запустіть `override` без шляху, щоб побачити всі шаблони, згруповані за видом генератора:

```sh
cargo loco generate override
```

Ця команда виводить дерево всіх доступних шаблонів плюс приклади викликів — вона ігнорує `--info` (голий виклик завжди виводить список).

## 2. Перегляньте конкретний файл або папку за допомогою `--info`

Перед копіюванням перевірте, що знаходиться за певним шляхом (без фактичного копіювання), додавши `--info`:

```sh
cargo loco generate override scaffold/frontend --info
```

## 3. Скопіюйте один файл, папку або все одразу

```sh
# перевизначити один файл шаблону
cargo loco generate override scaffold/api/controller.t

# перевизначити всі шаблони в папці (наприклад, усі frontend-сторінки скафолда)
cargo loco generate override scaffold/frontend

# перевизначити всі шаблони в проєкті
cargo loco generate override .
```

Скопійовані файли потрапляють у `.loco-templates/` (дзеркалячи вбудований шлях, наприклад `.loco-templates/scaffold/api/controller.t`), і команда виводить кожен скопійований файл. Якщо за вказаним шляхом нічого не знайдено, команда повідомить, що шаблонів не знайдено, замість тихо нічого не робити.

## 4. Відредагуйте свою копію

Відкрийте скопійований файл `.t` у `.loco-templates/` і редагуйте його як будь-який інший шаблон [Tera](https://keats.github.io/tera/) — він використовує ті самі змінні (`name`, `pkg_name`, фільтри регістру як `snake_case`/`pascal_case` тощо), що й вбудований шаблон, з якого ви його скопіювали. Наступного разу, коли ви запустите відповідний `cargo loco generate <kind> ...`, буде використано вашу локальну копію замість вбудованого шаблону.

## 5. Поверніться до вбудованого шаблону

Видаліть свою локальну копію — Loco завжди віддає перевагу `.loco-templates/`, коли вона існує, і повертається до вбудованого шаблону в ту мить, коли вона зникає:

```sh
rm .loco-templates/scaffold/api/controller.t
```

## Перевірте це

```sh
cargo loco generate override scaffold/api/controller.t
# відредагуйте .loco-templates/scaffold/api/controller.t
cargo loco generate controller widgets show
```

Переконайтеся, що згенерований `src/controllers/widgets.rs` відображає ваш відредагований шаблон (наприклад, доданий вами заголовок/коментар), а не стандартний вивід.

Дивіться [довідник генераторів і типів полів](/uk/docs/reference/generators/#override) для точної форми CLI-команди `override`, а також [довідник CLI](/uk/docs/reference/cli/#24-підкоманди-generate), щоб дізнатися, як `override` вписується серед інших підкоманд `generate`.
