<details>
<summary>Як автоматично перезавантажувати код?</summary>

Спробуйте [cargo watchexec](https://crates.io/crates/watchexec):

```
$ watchexec --notify -r -- cargo loco start
```

Або [bacon](https://github.com/Canop/bacon)

```
$ bacon run
```

</details>
<br/>
<details>
<summary>Чи потрібен мені `cargo` для запуску задач та інших речей?</summary>
Вам не обов'язково запускати речі через `cargo`, але під час розробки це настійно рекомендується. Якщо ви збираєте з `--release`, ваш бінарник містить усе, включно з вашим кодом, і `cargo` чи Rust не потрібні.
</details>

<br/>

<details>
<summary>Чи готовий він до продакшену?</summary>

Loco досяг версії 1.0 у липні 2026 року, що стало його першим стабільним релізом, але його коріння значно старіше. Це майже повне переписання `Hyperstackjs.io`, а Hyperstack базується на внутрішньому Rails-подібному фреймворку, який готовий до продакшену.

Більша частина Loco — це обв'язувальний код навколо Axum, SeaORM та інших стабільних фреймворків, тож ви можете це враховувати.

Як і з будь-яким фреймворком, оцініть Loco щодо вимог вашого застосунку та повідомляйте про проблеми, якщо вони виникнуть.

</details>

<br/>
<details>
<summary>Додавання власного middleware в Loco</summary>
Loco сумісний з middleware Axum. Просто реалізуйте `FromRequestParts` у вашій власній структурі та інтегруйте його у вашому контролері.
</details>

<br/>

<details>
<summary>Впровадження власного стану чи шарів у Loco?</summary>
Так, ви можете досягти цього, реалізувавши `Hooks::after_routes`. Цей хук отримує роутери Axum, які Loco вже побудував, дозволяючи вам безшовно додавати будь-які доступні функції Axum, які вам потрібні.

Якщо вам потрібно, щоб ваші маршрути чи обробник фолбеку (404) зазнавали впливу middleware Loco, ви можете додати їх у `Hooks::before_routes`, який викликається перед встановленням middleware.
</details>
