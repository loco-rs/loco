Тоді він виглядав би так:

```rust
async fn current(
    auth: middleware::auth::Auth,
    State(ctx): State<AppContext>,
) -> Result<Response> {
    let user = users::Model::find_by_pid(&ctx.db, &auth.claims.pid).await?;
    format::json(CurrentResponse::new(&user))
}

pub fn routes() -> Routes {
    Routes::new().prefix("user").add("/current", get(current))
}

```

## Знайомтеся: Loco

Loco — це вебфреймворк для Rust, натхненний Rails. Він містить _майже всі можливості Rails_ з максимально ергономічним Rust:

* Контролери та маршрутизація через [axum](https://github.com/tokio-rs/axum)
* Моделі, міграції та ActiveRecord через [SeaORM](https://www.sea-ql.org/SeaORM/)
* Відображення через [serde](https://serde.rs/json.html)
* Фонові завдання без зайвих зусиль, багаторежимні: у процесі, поза процесом, асинхронні через Tokio
* Mailer'и (розсилка пошти)
* Завдання (tasks)
* Наповнення даними (seeding)
* Конфігурація з урахуванням оточення
* Трасування та логування, безшовно інтегровані через [tracing](https://docs.rs/tracing)
* Генератори через [rrgen](https://github.com/jondot/rrgen)
* Аутентифікація «з коробки» (на кшталт `devise` у Rails)
* Набір для тестування: автоматичне очищення таблиць, наповнення фікстурами, автоматичні міграції, знімки (snapshots) і маскування даних

Це повноцінний full stack, без перебільшення.

## Чому не Rails?

Якщо вам подобається Ruby — користуйтеся Rails. Не витрачайте час на пошуки альтернативи заради продуктивності: Rails і Ruby достатньо хороші.

**Але якщо ви закохані в Rust**, тепер ви можете будувати компанії так, як rubyїсти будували їх роками — просто використовуйте Loco.

* Ви отримаєте **безпеку Rust, строгу типізацію, чудові моделі конкурентності та неймовірно стабільні бібліотеки й екосистему**. Побудували один раз — і забули про це.
* Розгортання — це копіювання **одного бінарника** на сервер.
* Ви отримуватимете **порядку 100 000 запитів/сек** без жодних зусиль. І 50 тисяч запитів/сек — вже з викликами до бази даних. Вам ніколи не знадобиться більше ніж кілька серверів. Та ви можете розгорнутися навіть на Raspberry Pi — і будете щасливі.

## Фреймворк для однієї людини

Натхненний [підходом DHH](https://world.hey.com/dhh/the-one-person-framework-711e6318), головний принцип Loco звучить так:

> Фреймворк для однієї людини

І з цього єдиного принципу випливає все інше.

Наприклад, команда з однієї людини або компанія з однієї людини:

* **Не має часу дискутувати про бібліотеки**, інструменти, правила лінтування: сильні та чіткі думки — це те, що треба. Просто скажіть мені, як працювати.
* **Потребує інструменту-двигуна** на додаток до власного розуму — це і є Loco CLI. Генеруйте код, керуйте проєктом.
* **Потребує стабільності**: будь-який збій — це втрачений час, будь-який сюрприз — це втрачений час.
* **Потребує простоти** — без сюрпризів, будь ласка.
* **Потребує єдиної історії експлуатації**. Розгортання має бути простим. Без Kubernetes, без IaC, без попередніх умов.
* **Потребує контролю**. Надсилайте листи й редагуйте їх локально, а не через якийсь віддалений сервіс.
* **Потребує локальності**. Все, що відбувається в продакшені, має спершу відбутися локально, у розробці.
* **Потребує гнучкості**. Жодних священних церемоній. Напишіть завдання, що надсилає привітання з днем народження вашим користувачам, замість того щоб розпочинати хрестовий похід за проєктом «Admin».

Loco — це фреймворк для однієї людини, створений для **інді-хакерів, ентузіастів і стартапів**.

З розгортальним бінарником близько **20 МБ і 50 тисячами запитів/сек** все, що вам потрібно, — це один невеликий або середній сервер, Postgres чи Sqlite та інтернет-з'єднання. Стартапи мають бути дешевими!
